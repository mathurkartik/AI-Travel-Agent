# 🤖 Prompt for Claude: n8n Product Teardown Generation

*Copy the text below the line and paste it into Claude to generate your Product Teardown.*

---

**System Role:** You are an expert Product Manager conducting a detailed product teardown for a PM assessment. Your goal is to reverse engineer the thought process behind an onboarding experience, analyze the UX, and propose improvements using a structured, analytical approach.

**Task:** Perform a comprehensive product teardown of the onboarding process for **n8n**, a fair-code, self-hostable AI workflow and automation tool.

**Format Requirements:** Please format the output as a professional Markdown document suitable for a GitHub repository or PM portfolio (e.g., `ProductTeardown_n8n.md`). Use clear headings, bullet points, and bold text for readability.

Please cover the following sections in detail, as required by the assignment:

### 1. Introduction & Company Context
- Briefly explain what n8n is and how it differentiates itself (fair-code, self-hostable, code-friendly).
- **Market & Actors:** Describe the automation/AI workflow market. Who are the key actors?
- **Business Model:** How does n8n make money (Cloud hosting vs. free self-hosted, enterprise tier)?

### 2. Target Users & Personas
- Who are the target users/customers for the onboarding process?
- Create a brief User Persona (e.g., "Technical Operations Lead" or "Developer seeking faster integration").
- **Segment Size & Impact:** How big is this segment, and what is the potential impact of capturing them through effective onboarding?

### 3. Customer Pain Points
- What specific customer pain points is the n8n onboarding process addressing? (e.g., "Other tools lack custom code flexibility," "Data privacy concerns with SaaS tools," "Blank canvas paralysis").

### 4. User Journey Mapping (The Onboarding Flow)
- Map out the hypothetical (or typical) step-by-step user journey from landing on the homepage, choosing between Cloud/Self-hosted, to creating their first successful workflow.
- **Friction Points:** Identify areas where users might get stuck, drop off, or feel overwhelmed (e.g., technical setup for self-hosting, understanding node configurations, API authentication).

### 5. Key Learnings & Takeaways
- What UX principles is n8n using well? (e.g., developer-friendly UI, template library, canvas layout).
- What growth principles are evident? (e.g., open-source community growth, templates as a growth engine).

### 6. Product Iterations (Improvements)
- As a PM, how would you improve the current onboarding product?
- Propose 2-3 specific product iterations to reduce friction and increase activation rates (especially bridging the gap for slightly less technical users without alienating developers).

### 7. Critical Metrics
- Define the critical metrics you would track to gauge the success of the onboarding flow.
- Break them down into Acquisition, Activation, and Retention metrics (e.g., Time to First Workflow, % of users executing their first node successfully, Drop-off rate at the credentials setup step).

**Tone:** Analytical, user-centric, and professional. Focus on "why" things are designed the way they are, rather than just describing "what" they are.
